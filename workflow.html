System Architecture

How the Running Hub Works

From finishing a run to seeing it in the dashboard — every step explained.

🏃 1
Patrick Finishes a Run
Strava Mobile App · GPS Watch
You finish your run and save it in the Strava app. Strava records the full activity — distance, pace, heart rate, cadence, splits — and marks it as a new activity in its system.
Strava App object_type: activity aspect_type: create
POSTwebhook event fired automatically
⚡ 2
Cloudflare Worker receives the webhook
patrick-strava-webhook.phadbq.workers.dev
Strava fires a POST request to this Cloudflare Worker within seconds of the activity being saved. The Worker checks object_type === "activity" and aspect_type === "create" — ignoring updates, deletes, and athlete events. It always returns HTTP 200 to Strava so Strava never retries.
Cloudflare Workers cloudflare-worker/index.js STRAVA_VERIFY_TOKEN
POSTrepository_dispatch → event_type: strava-activity
🔄 3
GitHub Actions workflow triggers
.github/workflows/sync-strava.yml
The Worker calls the GitHub API to fire a repository_dispatch event. GitHub Actions picks this up and starts a fresh Ubuntu runner. The workflow also runs on a daily cron at midnight Bangkok time as a fallback.
GitHub Actions ubuntu-latest GH_PAT (repo + workflow) cron: 0 17 * * * (UTC)
APIStrava v3 — fetch all activities
🐍 4
sync_strava.py runs
scripts/sync_strava.py · Python 3.12
The script exchanges the refresh token for a fresh access token, pulls all activities from the Strava API, and writes them to data/runs.json. It then prints the new refresh token so the workflow can rotate the secret — keeping OAuth alive without manual intervention.
STRAVA_CLIENT_ID STRAVA_CLIENT_SECRET STRAVA_REFRESH_TOKEN token rotation → GH secret
GITcommit data/runs.json + push to main
📦 5
runs.json committed to GitHub
worapratyy/patrick-running-hub · data/runs.json
GitHub Actions commits the updated data/runs.json back to the main branch with a timestamped commit message. If nothing changed (no new runs), the commit is skipped cleanly.
data/runs.json github-actions[bot] ~75 activities · ~60 KB
GETfetch('./data/runs.json') on page load
📊 6
Dashboard renders the data
index.html · dashboard.html · training-plan.html
The dashboard pages are plain HTML/JS hosted on GitHub Pages. On load they fetch data/runs.json directly from the repo and compute KPIs, charts, and training status — no server, no database, no build step required.
GitHub Pages Chart.js 4.5 zero dependencies VDOT · HR zones · pace
🔑 Secrets & Where They Live
STRAVA_CLIENT_ID GitHub repo secret · used by sync_strava.py
STRAVA_CLIENT_SECRET GitHub repo secret · used by sync_strava.py
STRAVA_REFRESH_TOKEN GitHub repo secret · auto-rotated every sync
GH_PAT GitHub repo secret · rotates STRAVA_REFRESH_TOKEN via gh CLI
STRAVA_VERIFY_TOKEN Cloudflare Worker secret · verifies Strava handshake
GH_PAT (CF copy) Cloudflare Worker secret · triggers repository_dispatch
⚡
From saving a run to seeing it on the dashboard takes roughly 60–90 seconds. The entire pipeline is serverless — Cloudflare Worker + GitHub Actions + GitHub Pages. Monthly cost: $0.
